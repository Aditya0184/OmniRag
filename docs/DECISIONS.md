# Architecture decisions

The first nine decisions record Phase 1. Phase 2 was authorized on 23 October 2026 and adds the implementation described in [PHASE2.md](PHASE2.md).

1. **Deliver one real vertical slice.** SQLite FTS5 implements an actual BM25 baseline now. Dense retrieval and fusion remain independently evaluated Phase 2 additions. Phase 1 is not advertised as semantic or hybrid search.
2. **Keep extraction replaceable.** pypdf provides a small text-PDF parser for the first module. Docling/OCR and rich format adapters follow after the application path is stable. Pages remain explicit provenance units.
3. **Use the standard SQLite driver initially.** This avoids ORM/migration scaffolding before the schema is stable. The repository layer centralizes SQL, uses parameter binding, and declares schema version 1. SQLAlchemy/Alembic remain options when logical versions, memberships and multi-user access are introduced.
4. **Persist ingestion outside request handlers.** The document row contains the Phase 1 job state. A separate worker uses leases and token-based stale-write prevention. Heavy parsing runs in a child process with a timeout. It is not an unbounded FastAPI background task.
5. **Treat model output as untrusted.** Structured JSON is parsed with Pydantic; all citations are resolved against retrieved chunks and exact normalized quotations. No arbitrary Python, SQL or shell execution is available to the model.
6. **Expose verification limits.** Quote provenance is checked. Semantic support, numerical correctness, confidence calibration, and general prompt-injection robustness are not established by this check.
7. **Run locally first.** There is no authentication yet. Default commands bind to loopback; browser origins and hostnames are restricted. These controls do not make this a multi-user enterprise service. VPS publication waits for authentication, authorization and deployment work.
8. **Constrain M1 memory.** One active model call per API process, four passages, 4K context, and a small quantized model. Local HTTP deliberately ignores proxy environment variables. The Mac run exposed truncation with the original thinking model at both 768 and 1,536 output tokens. The default is now the explicit 2B instruct variant, retaining 768 output tokens; context and concurrency stay unchanged. See the validation record for observed latency and memory pressure, which are not benchmark measurements.
9. **Separate checks from claims.** Mocked model tests establish adapter/error-handling behavior, not generation quality. The real-model smoke script is a separate acceptance gate. No research benchmark results are supplied.
10. **Use persistent Qdrant local mode for the Mac pilot.** One API process owns the vector directory; the PDF worker queues durable indexing jobs in SQLite. This avoids a Docker VM and multiple model copies. It is not a multi-process deployment design.
11. **Keep retrieval comparison explicit.** BM25 remains available. Dense cosine retrieval, reciprocal rank fusion and a small ONNX cross-encoder can be selected independently. Scores are not confidence, and dense candidates do not establish answerability. The authored fixture does not justify universal quality claims.
12. **Pin model artifacts as well as packages.** Store exact model revisions and file hashes in `models/retrieval.lock.json`; runtime verifies the local files. Use tokenizer-bounded secondary windows while retaining the original page/chunk provenance and saved citations.
13. **Migrate without rewriting the corpus.** Schema 2 adds durable vector state through an explicit transaction. A pre-migration backup was taken on the Mac. Semantic readiness is separate from successful PDF extraction; failures are visible and retryable without fabricating results.

14. **Add bounded local OCR before richer multimodal interpretation.** Phase 3 was explicitly authorized on 23 October 2026. Use installed Tesseract English OCR and locked PDFium rendering, one page at a time. OCR pages with fewer than 20 normalized native-text characters; preserve native text otherwise. Raster images, tables and diagrams are not semantically interpreted.
15. **Record transcription provenance without rewriting existing sources.** Schema 3 stores page extraction metadata separately from chunks. Existing indexed pages are marked native/legacy. OCR citations identify transcription, and original PDF bytes remain unchanged. Retry is restricted to failed documents; ready documents require future versioned reprocessing.
16. **Bound work and clean up descendants.** Limit OCR to 20 pages, approximately four megapixels per rendered page, one Tesseract thread, 20 seconds per OCR call, and the existing 90-second whole-document timeout. Kill the parser process group and remove its temporary directory on timeout. Fail the entire ingestion on an OCR execution error instead of silently indexing a partial result.

17. **Measure answer and OCR behavior before another retrieval architecture.** The user selected this Phase 4 direction on 23 October 2026. Use a versioned, authored fixture, deterministic synthetic PDFs, isolated SQLite/Qdrant storage, the actual worker, and the production query endpoint. Only explicit `--with-model` calls the installed loopback Ollama service. Record fixture/source hashes, package versions, OCR metadata and model identities; preserve per-query failures and refuse to overwrite earlier reports.
18. **Keep quality proxies and execution success distinct.** CER/WER compare reference transcription; answer fact matching uses whole token sequences; citations are checked against annotated pages as well as production quote provenance. These do not establish semantic entailment. Errors and invalid citations cannot count as successful abstention. Core quality gates and known-limit challenges are separate, with raw drafts/evidence available for manual review. Do not alter product behavior or fixture expectations to hide poor baseline results.
19. **Bind each new answer to a source excerpt.** Phase 5 follows the user's request for the next step after evaluation. Replace independent model-written claims/quotes with a small structured selection: explicit answerability plus at most two request-local excerpt IDs. The server constructs claim text and its citation from the same excerpt, then checks text equality and original chunk provenance. Existing history is not rewritten. This removes a demonstrated claim/quote mismatch but does not prove question relevance or source truth.
20. **Preserve abstention as a distinct decision.** ID selection alone answered one question using another company's policy. Require explicit answerability, same-entity and requested-fact instructions, and retain all candidate experiments. The final baseline still has a paraphrase abstention and the existing mixed-content OCR gap. No retries, second judge, new models or hidden fallback are introduced.
21. **Use bounded extractive spans and expose their limits.** Excerpts are whitespace-normalized sentence spans of 12–240 characters; short fragments are joined forward and overlong spans are skipped, never cut just to fit. At most two spans become answers. Simple sentence splitting and existing chunks can lose context; the app labels the result as source excerpts and still opens original pages. Model-written summaries, numerical synthesis and region-aware OCR remain outside this step.

22. **Recover sparse mixed pages with a bounded heuristic.** Phase 6 follows the user's continuation after Phase 5. For 20–199 native characters, OCR the full page when a top-level raster bounding box occupies at least half its visible area. Keep the original low-text fallback and all resource limits. Record the trigger and extractor version, avoid summing overlaps or duplicating headers, and label the entire transcription OCR. This is not region-aware extraction and can miss smaller, tiled, nested or native-heavy mixed layouts.
23. **Do not silently accept only a detected mixed page's header.** A mixed-content candidate requires enabled OCR; an OCR execution failure or unusably short result fails ingestion. Preserve original bytes, ready documents, old metadata and saved answers. Keep the original quality fixture and answer logic fixed so the measured change is attributable to extraction.

24. **Assess the requested fact before selecting excerpts.** Phase 7 follows the user's next-step request after OCR validation. A bounded model-generated assessment precedes explicit record-requirement/support flags and the existing answerability/source-ID selection. The server discards the assessment; answers still come only from validated source spans. This adds one-call selection guidance, not a semantic proof or a second judge. Preserve rejected candidates and evaluate unsupported questions alongside paraphrase recovery.
25. **Keep policies and individual records distinct.** When the model marks an individual record required but absent, the server withholds the selected excerpts after validating the output schema and source IDs. General first-person policy questions remain eligible. Test both absent and supplied records; record a policy version and withholding flag without storing freeform assessments. Keyword retrieval stays lexical, so BM25 no-match cases remain visible in the unchanged strict gate.
26. **Keep short linked conditions in one source span.** A literal repeated-phrase reference in the next sentence may join it to the preceding sentence, within one chunk and the 240-character quote limit. Remove the partial alternatives so selection can retain the condition. Do not merge every adjacent sentence: replay testing found that broader merging added irrelevant facts and regressed previously answered paraphrases. This English heuristic preserves provenance, not semantic completeness.

27. **Present source pages in reading order to the selector.** Keep document rank but group each document’s retrieved passages by page. The procurement browser failure reproduced when the acceptance page preceded the delivery policy; the same evidence answered after page ordering. Public retrieval evidence and scores stay unchanged. This reduces one observed order sensitivity, not all model instability.

28. **Measure selection stability before further tuning.** Phase 8 follows the user's next-step request after the Phase 7 activation. Replay all 41 fixed hybrid cases with retrieved and reversed passages, twice each, through the existing adapter. Retain question/fact expectations, distinguish changed selector inputs from repeatability, and count errors as failures. Stable wrong answers are still wrong. This audit adds no production fallback or model change and is not a held-out benchmark.

29. **Retry a valid policy abstention within existing resource limits.** Phase 9 follows the user's continuation after the audit identified three repeatable policy misses. Preserve the original first pass; permit at most one shorter policy prompt over identical excerpts when record, event, missing-name and remaining-budget checks allow it. Invalid output and request errors never trigger a retry. Sum usage, save one final result and retain exact source binding. English capitalization/event cues are conservative heuristics, not entity resolution or proof of support. The final local audit passed 164/164 observations and fresh hybrid evaluation passed 41/41; keep the three lexical no-match failures visible and treat these authored cases as development evidence. See [Phase 9 validation](PHASE9_VALIDATION.md).

30. **Keep the expanded delivery on the user's Mac.** The user included evaluation, authentication and deployment, then chose local Mac hosting. Serve the built UI from the loopback API, add one owner with salted scrypt credentials and revocable server-side sessions, require CSRF for authenticated writes, and preserve corpus storage. A launcher verifies process ownership and avoids duplicate service starts. No public hosting or multi-user isolation is implied. See [Mac operation](PHASE10.md).

31. **Preserve fresh evaluation failures instead of calling prior regressions general accuracy.** Freeze new entities, facts and questions before inference, retain Phase 9 generation and archive all outcomes. The new run passed 19/24 hybrid contracts and 17/24 BM25 contracts; three unsupported questions were wrongly answered in each mode. Authenticated deployment does not fix answer semantics. Keep the report and UI limitations explicit and do not call same-assistant authored tests an independent human evaluation. See [Phase 10 validation](PHASE10_VALIDATION.md).

32. **Restrict answer selection to the named subject and requested attribute.** Phase 11 follows the user's request to finish the private Mac project after the Phase 10 quality failures. Filter model context using conservative name and exact record-code constraints without altering public retrieval evidence; refuse without inference when no source survives. Clarify attribute selection for what/which/whose questions while retaining the existing guarded retry and source-quote binding. Freeze a separate new fixture before candidate work, preserve rejected candidates and old failures, and distinguish fresh acceptance from development regressions. The observed results are 48/48 new acceptance contracts, 89/89 fresh hybrid cases, 85/89 BM25 cases and 260/260 replay observations. These authored cases do not establish independent general accuracy. See [Phase 11 validation](PHASE11_VALIDATION.md).

33. **Let the model write grounded answers instead of forcing excerpt selection.** Phase 12 follows the user's report that ordinary broad questions returned insufficient evidence or unrelated excerpts. The extractive binding (Phase 5) prevented claim/quote mismatch but made whole-document, list, summary and explanation questions structurally unanswerable. The grounded path keeps every hard guarantee that remains checkable server-side: quotes must exist verbatim in retrieved chunks, written claims must be lexically supported by their citations, numbers must be conserved from the cited text, and foreign record codes are dropped. The Phase 5-11 excerpt mode remains selectable via `OMNIRAG_ANSWER_MODE=extractive` with its tests intact. See [PHASE12.md](PHASE12.md).
34. **Make refusal guards soft, not silent.** The Phase 11 literal subject filter refused before inference when it emptied the evidence; the record gate overrode the model after inference. Both caused supported answers to vanish. Phase 12 keeps the subject filter as focus-only (it relaxes and reports instead of refusing) and moves the policy/record distinction into the prompt plus deterministic post-checks (record-code guard, claim support). Refusals now carry a reason and a next step.
35. **Answer whole-document questions from coverage, not similarity.** "What is in this PDF?" retrieves nothing useful by ranking. Overview intents read chunks in document order within a bounded budget, disclose partial coverage explicitly, and clarify with a document list when the intended document is ambiguous. Explicit summarize/key-points requests use the cached or freshly generated overview instead of re-answering from scratch.
36. **Generate overviews after ingestion; never fail a document for it.** The worker generates one bounded overview call per newly ready document. Older documents are summarized on demand rather than backfilled at startup, because overview generation contends with owner queries for the single local model slot. Failures are recorded visibly and retryable.
37. **Evaluate before and after: frozen acceptance, separate development set.** `evaluation/broad_dev.json` drove prompt and threshold iteration; `evaluation/acceptance_v3.json` was frozen before implementation, amended twice only for scoring-contract corrections and fixture completion before its first run, with both amendments recorded in its freeze file. The assistant authored both sets; neither is independent human review.
